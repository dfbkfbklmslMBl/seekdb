| 事实 | 证据 |

## 路线 A：WSL2（推荐，与判题环境一致）

**前提：需要重启一次。** WSL 的两个功能已启用但 `RestartNeeded: True`，至今未重启（`LastBootUpTime` 仍是 2026-10-28 18:35:55）。

```powershell
# 重启后，PowerShell（管理员）
wsl --install -d Ubuntu-24.04        # 或 wsl --update 后 wsl --install -d Ubuntu
wsl -d Ubuntu-24.04
```

```bash
# WSL 内
sudo apt update && sudo apt install -y git cmake ninja-build python3 rsync curl wget ca-certificates
git clone git@github.com:oceanbase/seekdb.git ~/seekdb
cd ~/seekdb && git fetch origin 2026-competition && git checkout -b work origin/2026-competition
./build.sh release --init            # 拉依赖（走 el9 兼容表）
cd build_release && ninja -j$(nproc) seekdb   # 或 make -j$(nproc) seekdb
```

**风险与备选**：若 `--init` 在 apt 环境失败（它按 el 系列写），改用 **EL9 系发行版**更稳：
`wsl --install -d AlmaLinux-9`，或从 rootfs 导入 Rocky 9 / Alibaba Cloud Linux 3（对应 al8 表），
这样依赖表与包管理器原生一致。**这条备选我没有实跑过，标注为待验证。**

**已知限制（诚实标注）**：
1. `docs/developer-guide/en/build-and-run.md` **没有 Windows 章节**（grep 无命中），Windows 路径的权威说明只有 `build.ps1` 自己的注释；
2. 内核题的验收是 `tools/deploy/mysql_test`（bash 脚本 + obclient + 部署脚本），**Windows 上能否跑通完全未验证**——
   即使编译成功，可能只能做「编译检查 + 手工 SQL 验证」，跑不了官方用例；
3. MSI 打包还需要 WiX v4（`dotnet tool install --global wix`），但内核题不需要出包。
